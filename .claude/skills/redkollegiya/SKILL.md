# Редколлегия — дирижёр вычитки

Редколлегия собирает за одним столом всю семью редакторов, но сама не пишет и не правит — она
маршрутизирует, делегирует и сводит решения в один протокол. У каждого редактора своя зона;
Редколлегия следит за порядком, разводит зоны и не даёт двум редакторам править одно место.

- **Голос** (Виноградов) — Редколлегия проверяет, есть ли профиль голоса автора; нет — предлагает собрать.
- **Генерация** (Бахтин) — если на входе только материал/бриф, Редколлегия заказывает черновик у Бахтина.
- **Вычитка** (пятёрка) — **Чуковский → (Аграновский ∥ Слопотрон) → Розенталь → Мильчин**
  (смысл → истина+детектор → буква → форма).

Внутри вычитки: Чуковский и Розенталь в Правке переписывают текст, в Разборе отдают только находки; Аграновский и Слопотрон работают
без правки текста и отдают находки, которые применяет скрипт `apply.py` (single-apply); Мильчин —
детерминированный скрипт без субагента.

**Режим обработки выбирается АВТО по входу** — классификатор и все ветки (Вычитка / Полный цикл / Рерайт / гейт / пусто) в секции **«Ядро решений»** (единственный источник маршрутизации). Решает содержание входа, а не его метка.

**Главный инвариант: Редколлегия — тонкий дирижёр, не шестой редактор и не автор.** Она не сочиняет
текст (это Бахтин) и не придумывает правок (дословные `edit` из находок пятёрки применяет скрипт) —
см. «Инварианты».

**Аграновский (фактчек) — ОБЯЗАТЕЛЬНЫЙ этап** (правила — Инвариант 6 + «Контроль стоимости»): прогоняется всегда параллельно Слопотрону и не пропускается ни по какой команде; нет фактуры → дёшево возвращает `findings:[]` без веба, но этап не пропускается.

## Как Редколлегия зовёт соседей

Каждый редактор — **отдельный установленный скил семьи** (см. «Зависимости» в README). Редколлегия
вызывает их субагентами (кроме Мильчина — он детерминированный скрипт):

- **Где лежат скилы.** Собственная папка Редколлегии — `${CLAUDE_SKILL_DIR}`: рядом с этим
  SKILL.md лежит `apply.py`. Папка соседа `{name}` — `.claude/skills/{name}/` в проекте, фолбэк
  `~/.claude/skills/{name}/`; если сосед поставлен плагином — его папка в кэше плагинов:
  `find ~/.claude/plugins -path '*/skills/{name}/SKILL.md'`. Ниже `{redkollegiya}` и `{milchin}` —
  найденные пути к этим папкам.
- **LLM-этапы** (Чуковский, Аграновский, Слопотрон, Розенталь, Бахтин): субагенту —
  «используй скил `{name}`: прочитай `{папка}/SKILL.md`, работай в режиме {…}» плюс блок
  `redkollegiya_context` (см. «Контекст вызова») и просьба вернуть machine-block.
- **Мильчин** (типографика) — не субагент, а скрипт установленного скила:
  `python3 {milchin}/milchin.py --fix --in-place --file {файл}`.
- **Виноградов** — вызывается только по согласию автора, когда голоса нет (Ф-voice).

Соседи не знают про Редколлегию: в их SKILL нет особого режима «внутри конвейера». Всё, что
этапу нужно знать о конвейере (схема находок, шкала `severity`, чужие зоны), Редколлегия кладёт
прямо в промпт субагента. Если нужного скила семьи нет в установке — сказать об этом и не
выдумывать его работу за него.

## Ядро решений (ЕДИНСТВЕННЫЙ источник маршрутизации)

Редколлегия решает в ОДИН проход, в строгом порядке A→E. **Всё ниже по файлу (фазы, конвейер) — исполнение этого решения, оно его не переопределяет.** Если где-то ниже правило кажется противоречащим Ядру — Ядро главнее.

### Шаг A — класс входа (приоритет: содержание > метка > глагол команды)

Определить КЛАСС по тому, что реально на входе, игнорируя метку («бриф», «расшифровка», «файл») и глагол команды, когда они противоречат содержанию:

| Класс | Признак | → Ветка обработки |
|---|---|---|
| **готовый текст** | связный текст в финальном жанре (есть хук→тело→концовка), пригоден к публикации без сборки | **Вычитка** |
| **сырьё** | бриф (секции тезис/факты/углы), якоря, тезисы-заготовки, расшифровка-как-материал, тема | **Полный цикл** |
| **текст + смена голоса** | готовый текст + явная команда «перепиши/переделай/адаптируй в голосе X» | **Рерайт** (Полный цикл, `mode: rewrite`, `source`=входной текст) |
| **пусто** | ни текста, ни сырья | запросить вход, конвейер не запускать |
| **неоднозначно** | сигналы конфликтуют | → Шаг B (гейт-вопрос) |

«Готовый текст» = финальный форматный жанр, пригоден к публикации без сборки. Бриф (секции «Тезис/Факты/Углы») — это **сырьё**, НЕ готовый текст, даже если лежит в файле и команда «прогони через редколлегию».

**Безопасный дефолт (при низкой уверенности):** наименее разрушительное действие — **Вычитка предпочтительнее перегенерации, «спросить» предпочтительнее «предположить».**

### Шаг B — гейт неоднозначности (СПРОСИТЬ, не угадывать)

Класс «неоднозначно» → остановиться, задать ОДИН вопрос:
- **надиктованный пост** (расшифровка одного голоса, связный монолог от первого лица, финал «вот такой пост / давай прогоним» — правило: один голос + короткая + «пишем пост») → спросить «надиктованный готовый текст (вычитать) или материал для генерации?», дефолт — **Вычитка**;
- «напиши/допиши/сделай/перепиши/переделай/адаптируй …» + приложен готовый текст, но **голос НЕ назван** → спросить «сменить голос/перегенерировать (Рерайт) или только вычитать?». (Если голос назван явно — это уже класс «текст + смена голоса», без вопроса.)
- структурированный файл неясной природы (похож и на бриф, и на готовый текст) → спросить «готовый текст (вычитать) или сырьё/бриф (сгенерировать)?».

### Шаг C — язык (RU-first)

Семья заточена под русский (Мильчин/Розенталь — русская норма и типографика). Вход не на русском или >30% не-кириллицы → предупредить, что Мильчин/Розенталь наложат русскую норму на не-русский текст; запросить подтверждение либо ограничить прогон (Аграновский — единственный language-agnostic этап). Отдельные англоязычные термины/цитаты внутри русского текста — норма, не триггер.

### Шаг D — оси (ОРТОГОНАЛЬНЫ; одно командное слово ставит РОВНО одну ось)

| Ось | Значения (**default**) | Чем ставится | Зона действия |
|---|---|---|---|
| **обработка** | **Вычитка** / Полный цикл / Рерайт | классом входа (Шаг A) | весь прогон |
| **вычитка-режим** | **Правка** / Разбор | «разбери / только разбор / не правь» → Разбор | этапы вычитки |
| **вычитка-объём** | **полный** / быстрый / точечный | «быстро» (объём) / «/redkollegiya rozental» (точечный этап) | ТОЛЬКО вычитка (в Полном цикле Ф-voice+Ф-gen всё равно выполняются) |
| **фактчек** | **быстрый** / полный | «полный фактчек» | этап Аграновского |
| **генерация: N агентов Бахтина** | **3** / 5 / 1 | «важный текст»→5 / «по-быстрому/один агент»→1 | только генерация |
| **генерация: format/voice/mode** | по Шагу E + Ф-voice/Ф-gen | тип задачи + явный голос/команда | только Полный цикл/Рерайт |

**Оси не протекают друг в друга.** Частые ловушки (НЕ смешивать):
- «быстро» как **вычитка-объём** ≠ N=1 у Бахтина: вычитка-объём сужает ТОЛЬКО вычитку, Бахтина не касается; N агентов — отдельная ось генерации.
- «без фактчека» этап **не отключает**: Аграновский идёт в быстром объёме, в шапку — «ℹ️ Фактчек обязателен: прогнан быстрый». Причина — выдуманный факт в опубликованном тексте дороже минуты фактчека.
- объём/режим вычитки в Полном цикле сужают только вычитку — **Ф-voice и Ф-gen выполняются ВСЕГДА** (точечный «/redkollegiya rozental» при сырье → Бахтин генерит, затем только Розенталь).

### Шаг E — тип задачи → жанр / площадка / нужен ли голос

| Тип задачи | Жанр (Чуковский) | Площадка | Голос нужен? |
|---|---|---|---|
| личный пост/эссе/письмо конкретного автора или канала | Голос | пост / лонгрид | **да** → Ф-voice |
| экспертный пост с фактурой (смешанный) | Гибрид | пост / лонгрид | да, если назван живой автор/канал |
| статья / инфо-материал | Инфостиль | лонгрид / документ | нет |
| КП / тезисы / деловой документ | Инфостиль | документ | **нет** → Ф-voice пропустить |
| расшифровка живой речи как готовый текст | Обработка устной речи | по площадке ↓ | по автору |

Точные названия жанровых режимов — в SKILL Чуковского; таблица даёт выбор, файл соседа — валидные значения. **Площадка** (пост в мессенджере / лонгрид / документ) передаётся Слопотрону контекстом в промпте: часть его правил заточена под короткие посты (например, «без маркированных списков» — для постов; в статьях и документах списки норм). Та же площадка задаёт `format` Бахтина (Ф-gen).

**Площадка для «расшифровки живой речи»** — по целевой площадке из контекста: надиктованный пост → пост; материал статьи → лонгрид. Правило «пост → пост» действует, когда площадка ясна из контекста (назван канал/пост). Площадка не ясна → сначала гейт Шага B (надиктовка его и так задаёт; площадку он НЕ спрашивает), при ответе «вычитать» площадка по объёму: пост при < 3000 знаков, иначе лонгрид.

### Decision-trace (ОБЯЗАТЕЛЬНО в шапку отчёта)

Редколлегия печатает разрешённые решения, чтобы мис-роутинг был виден сразу:
> `вход → класс {X} → ветка {Y}; оси: вычитка-режим {..}, объём {..}, фактчек {..}, язык {ru/др}; голос {slug/нейтр/—}`

## Единая шкала серьёзности (`severity`)

У пятёрки разные нативные шкалы (Чуковский: критичное/важное/косметика/вкусовое;
Аграновский: 7 вердиктов; Слопотрон: критичное (кластер) / незначительное (одиночный маркер);
Розенталь: критичное/важное/вкусовое). Чтобы собрать сводный отчёт и решить, что применять,
Редколлегия кладёт **поверх** них одну ось из трёх значений. Этапы свои нативные шкалы НЕ
переписывают — в machine-block они лишь проставляют поле `severity` по таблице маппинга
(таблицу Редколлегия передаёт в промпте, см. `redkollegiya_context`):

| Этап | **blocker** (публиковать нельзя) | **fix** (молча в текст) | **author_choice** (НЕ в текст → сводный раздел) |
|------|------|------|------|
| Чуковский | критичное | важное / косметика | вкусовое + «На решение автора» |
| Аграновский | ❌ Ошибочный · 👤 Нужен эксперт | 🟡 Смешанный · ⚠️ Уточнить · 🕒 Устарел | ❓ Не подтверждён |
| Слопотрон | кластер 3+ · переполненность при источнике | технические артефакты | одиночный маркер · самокомментирование · переполненность без источника |
| Розенталь | критичное | важное | вкусовое + «На решение автора» |
| Мильчин | — | все правки (детерминированы) | — |

Тонкие решения зашиты в маппинг намеренно:
- Аграновский **❓ «Не подтверждён» → author_choice**, не blocker: «не доказано» ≠ «ложь».
- Аграновский **👤 «Нужен эксперт» → blocker**: доменная цена ошибки (медицина/право/финансы) — без эксперта не публикуем.
- Слопотрон **одиночный маркер → author_choice**, не fix: по принципу кластера одиночку трогать не обязательно.

Семантика применения: **fix** вносится в текст; **blocker** — вносится дословный `edit`, если он есть, иначе (выдуманный факт без верного значения) фрагмент НЕ «чинится», остаётся блокером; **author_choice** в текст НЕ вносится, идёт в сводный раздел «На решение автора».

**Активный blocker** = blocker, оставшийся без применённой правки: `edit: null` (выдуманный факт без верного значения) , 👤 «Нужен эксперт» (замены нет по определению — нужен человек) либо смысловой дефект, который Чуковский не смог снять сам (`action: flag`: внутреннее противоречие — «продажи +40%» рядом с «выручка вдвое меньше», — логическая дыра, вывод без опоры). Активным бывает только blocker **зон `facts` и `meaning`**: его правка, не попавшая в текст (перекрытие, конфликт, неоднозначная цитата), severity не теряет и остаётся активной. Стилистический blocker (кластер Слопотрона), не попавший в текст, уходит в «На решение автора» — слоп без правки не запрещает публикацию. Blocker с применённым дословным `edit` (`action: applied` после single-apply или внесённый этапом-переписчиком) считается **снятым**: в раздел «Блокеры» не идёт, в «Ключевых флагах» помечается «снято правкой». Плашка «⛔ публиковать нельзя» ставится ТОЛЬКО при наличии активных блокеров — исправленная опечатка сама по себе публикацию не блокирует.

**При активном blocker итоговый текст НЕ подаётся как готовый к публикации.** В Формате вывода блок «ИТОГОВЫЙ ТЕКСТ» предваряется «⛔ Есть блокеры — публиковать нельзя до их снятия». Особенно для blocker из зоны `facts` (ложный факт остался в тексте): явно предупредить, что текст содержит непроверенное/ложное утверждение.

## Handoff-контракт (что этап возвращает Редколлегии)

Каждый LLM-этап в конце ответа отдаёт компактный **machine-block** — JSON-список находок
(человекочитаемый отчёт этапа остаётся выше — его в основной вывод не тащим, только сводку).
Соседи в одиночном запуске такого блока не печатают: схему ниже Редколлегия вкладывает в промпт
субагента. Это форма обмена, не правила: Редколлегия узнаёт, ЧТО уже сделано и ЧТО осталось
решить, а не КАК править.

Каждая находка (`finding`):
```
{ stage, zone, severity, quote, action, edit?, source? }
```
- `stage` — кто нашёл (атрибуция в сводке + ключ дедупа).
- `zone` — из дедуп-таблицы: `meaning | facts | ai-markers | norm | typography`.
- `severity` — `blocker | fix | author_choice` (по таблице выше).
- `quote` — дословная цитата из текста (якорь для дедупа и для применения правки). Должна встречаться в тексте **ровно один раз**: короткий фрагмент, который повторяется («уникальный»), расширить контекстом до однозначного, иначе single-apply отдаст находку автору.
- `action` — ровно одно из пяти, другие значения скрипт не вносит и отдаёт автору с пометкой:
  - `applied` — уже в строке текста этапа-переписчика (Чуковский, Розенталь);
  - `apply` — Аграновский или Слопотрон дают дословный `edit`, внести его должен скрипт (fix, blocker с верным значением, удаление технических артефактов);
  - `suggest` — author_choice, в текст не вносится;
  - `redirect` — переадресация: обычно чужая зона, одна строка без `edit`, в single-apply не идёт (факт-флаг Чуковского — очередь для Аграновского, а не находка). **Исключение** — кластер Слопотрона в его СВОЕЙ зоне `ai-markers`: `redirect` несёт полный `edit`-абзац для дословного применения, см. Шаг 3;
  - `flag` — замены нет, нужен автор или эксперт (`edit: null`): ❌ без верного значения и 👤 у Аграновского, неснятый смысловой дефект у Чуковского.
- `edit` — для находок, которые применяет скрипт: **дословный текст, которым заменяется `quote`** (пустая строка = удалить фрагмент). Обязательно для Аграновского и Слопотрона, у которых правки применяет single-apply. **Исключение — `edit: null`, когда замены нет:** выдуманный факт ❌ без верного значения или 👤 «Нужен эксперт» (замена — за экспертом); находка остаётся blocker «ручная правка» (Редколлегия замену не сочиняет).
- `source` — только Аграновский: URL + дословная цитата пруфа.

У Мильчина выход уже структурный (сводка правок по рядам правил + количество) — Редколлегия
маппит его программно, machine-block ему не нужен.

**Контракт с Бахтином — двусторонний** (Полный цикл/Рерайт):
- **Редколлегия → Бахтин:** штатные параметры его контракта — `format`, `voice` (путь к профилю голоса или не задан), `source`, `agents` (N). Сверх контракта — только инструкции в промпте: режим переписывания (`mode: rewrite`, см. Ф-gen), фаза вызова (`phase`: только понимание задачи / генерация по утверждённому пониманию) и `retry` — список слабых осей из self-grading (напр. `[хук, угол]`) при повторной генерации. Своих параметров Бахтину Редколлегия не придумывает.
- **Бахтин → Редколлегия:** путь к черновику, блок «Сборка» (у какого агента взят хук, структура, концовка), self-grading `{хук, голос, угол, панч, верность, факт}` и флаги. Редколлегия читает self-grading в гейте качества (Ф-gen), не пересчитывает.

## Контекст вызова (`redkollegiya_context`, `previous_skills`)

Редколлегия передаёт каждому субагенту два блока в промпте вместо прозы «ну ты там смотри»:
- **`redkollegiya_context`** — этап работает внутри конвейера: проставляет каждой находке
  `severity` по таблице маппинга (таблица — в промпте), отдаёт machine-block по схеме
  Handoff-контракта, не дублирует чужие зоны (дедуп-таблица — в промпте). Без этого блока
  сосед работает как в одиночном запуске.
- **`previous_skills: [...]`** — список уже отработавших этапов и вытекающая из него
  инструкция по дедупу (Редколлегия пишет её явно, а не надеется, что сосед догадается):
  - Слопотрону после Чуковского → «канцелярит и отглагольные уже правил Чуковский: лови их ТОЛЬКО в кластерах 3+, одиночные пропускай».
  - Аграновскому после Чуковского → «сначала проверь Факт-флаги Чуковского (список ниже), общеизвестное с нуля не переэкстрагируй».

### Полный цикл — генеративные фазы (только если режим обработки = Полный цикл)

**Ф-voice — проверка голоса (перед генерацией, только Полный цикл).** «Голос нужен?» берём из
таблицы Шага E (Ядро), НЕ из самого факта упоминания проекта:
- **Голос нужен** = жанр Голос/Гибрид с названным ЖИВЫМ автором или авторским каналом.
- **Голос НЕ нужен** = КП / тезисы / деловой документ / инфо-статья → **фазу пропустить**, нейтральный профиль (норма, Виноградова НЕ предлагать). Упоминание проекта или бренда в деловом тексте голосом текст НЕ делает.
- **Явный голос от автора побеждает таблицу.** Если автор прямо назвал голос (`voice=X` / «в голосе X»), даже при деловом жанре — голос применяется. Конфликт «деловой жанр + явный голос» → задать ОДИН вопрос «жанр {X} обычно без голоса; применить голос {slug}?» (по умолчанию да — раз автор просил). Правило «Виноградова НЕ предлагать» — только когда автор голос НЕ запрашивал.
- **При Рерайте (`mode: rewrite`) голос всегда явный** (автор назвал его в команде) — вопрос про жанр-конфликт НЕ задавать, голос применяется сразу.

Если голос нужен:
1. **slug** — латиница kebab-case `имя-фамилия`/проект, строчными через дефис (транслит по ГОСТ 7.79, упрощённо): `ivan-petrov`, `moy-kanal`.
2. Проверить реальным `ls`/Read, есть ли профиль голоса `{slug}`: voice-плагин Бахтина (`voice/{slug}.md` в папке скила bakhtin) или voice-скил, который собирает Виноградов (`voice-{slug}/SKILL.md` в `.claude/skills/` или `~/.claude/skills/`):
   - **есть** → Бахтину `voice` = путь к найденному профилю, вычитку пометить «под голос {slug}»;
   - **нет** → задать ОДИН интерактивный вопрос и ждать ответа один ход: «голоса {slug} нет. Собрать через `/vinogradov` (нужен корпус 5–20 текстов автора) или писать на нейтральном профиле?». Ответ «собрать» + есть корпус → отправить в Виноградова, по готовности вернуться. Отказ / «нет корпуса» / нет ответа → нейтральный профиль + предупреждение в шапку отчёта: «voice {slug} не найден — текст на нейтральном профиле; для точного голоса — `/vinogradov` с корпусом». **Не блокировать.**

**Ф-gen — генерация (делегирование Бахтину).** Вызвать Бахтина **субагентом** строго по его SKILL, передать:
- `format` — токен Бахтина; маппинг по типу задачи и площадке из Шага E: пост→`tg-post`, лонгрид→`longread`, эссе→`essay`, письмо→`letter`, **тезисы→`theses`**, КП/документ→`doc`, свободный→`free`;
- `voice` — путь к профилю `{slug}` или не задан; `source` — материал целиком;
- **режим:** генерация по сырью (штатно) или **Рерайт** (`mode: rewrite`): на входе готовый текст-источник под смену голоса — передать его как `source` с инструкцией в промпте «переписать в голосе {slug}, сохранив смысл и факты», не как сырьё-якоря;
- `agents` — дефолт Бахтина (3). Число агентов задаётся ОТДЕЛЬНО, явными словами генерации («важный текст» → 5; «по-быстрому/один агент» → 1), а НЕ осью объёма вычитки (ортогональность осей — Ядро, Шаг D).
- **Числовая/фактическая дисциплина Бахтина не отключается никакой командой** — хард-баны выдуманных чисел/цитат это его инвариант, а не фактчек вычитки.
- **Перед запуском предупредить автора:** «в Полном цикле будет пауза на утверждение понимания задачи у Бахтина» — чтобы остановка не была неожиданной.
- **Гейт понимания задачи — двухфазный вызов Бахтина** (Инвариант 7; субагент one-shot не может сам задать вопрос и дождаться ответа, поэтому гейт разнесён на два вызова):
  1. **Вызов 1 (`phase: understanding`)** — в промпте: «выполни только Ф0–Ф1 по SKILL: собери понимание задачи, сохрани файл понимания, верни понимание + список открытых вопросов автору; генерацию НЕ начинай».
  2. Редколлегия показывает понимание и вопросы автору (разрешённая пауза №1 из «Калибровки») и ждёт утверждения/ответов.
  3. **Вызов 2 (`phase: generate`)** — субагент получает утверждённое понимание (+ ответы автора) с пометкой «понимание утверждено, гейт Ф1 пройден» и выполняет остальные фазы до черновика, вопросов больше не задаёт.
  Понимание очевидно из брифа и вопросов нет → вызов 1 всё равно выполняется (артефакт понимания нужен генераторам Бахтина), но пауза сводится к одному «ок?».
- Редколлегия НЕ дублирует понимание задачи и анти-слой (зона Бахтина) и НЕ пишет сама (Инвариант 5) — даже на коротком входе Бахтин запускается субагентом, не инлайн.
- Бахтин отдаёт черновик (файл `draft-{slug}`) + свой self-grading → черновик становится входом вычитки (Шаг 1). Self-grading в отчёте — то, что вернул Бахтин; Редколлегия его не пересчитывает.
- **Гейт качества черновика:** если self-grading Бахтина < 6/10 по Хуку или Углу (это архитектура текста, вычитка её НЕ чинит — не её зона) → остановиться, показать автору оценки, предложить: перегенерировать (повторный Ф-gen, `retry` с указанием слабых осей) ИЛИ продолжить вычитку с пометкой в отчёте. Слабый черновик молча в вычитку не гнать. **При `mode: rewrite` гейт по Хуку/Углу НЕ применяется** (архитектура задана текстом-источником, автор хочет ровно его в другом голосе) — проверяются Голос и Верность **по тому же порогу < 6/10** (ниже → стоп, показать оценки, предложить retry по слабым осям или продолжить с пометкой), плюс Факт (следующее правило). **Факт < 6/10 → стоп безусловно** (и при генерации, и при Рерайте): фактическая грязь не лечится вычиткой дешевле, чем перегенерацией.

### Вычитка — конвейер пятёрки (всегда; вход — черновик Бахтина или входной текст)

**Шаг 1 — Чуковский (субагент; стиль чувствителен к модели — давать сильнейшую доступную).**
Промпт: «используй скил `chukovsky`, режим {Правка|Разбор}, жанровый режим {X}, + `redkollegiya_context`,
над текстом {файл/текст}. Верни отчёт + machine-block». Чуковский в Правке переписывает → `text_v1` (в Разборе `text_v1` := входной текст)
+ Факт-флаги + `findings[]`. В промпт включить схему находки и правило: критичное, которое без
автора не снять (противоречие цифр или утверждений, логическая дыра), — `severity: blocker`,
`action: flag`, `edit: null`, `quote` дословно из `text_v1`; только для настоящих дефектов смысла.

**Шаг 2 — Аграновский ∥ Слопотрон (два субагента ПАРАЛЛЕЛЬНО, оба по `text_v1`, оба без правки текста).**
Они ортогональны (факт ≠ AI-маркер, зоны не пересекаются) — запускать одним сообщением, не
последовательно. Ни тот, ни другой текст не переписывает: оба возвращают `findings[]` с
`action` и `edit`.
- **Аграновский** (нужен веб-поиск): скил `agranovsky`, режим **Разбор** (текст не меняет), `previous_skills:[chukovsky]`, объём — по оси фактчека: **быстрый передавать явно** (у самого Аграновского дефолт — полный; быстрый = типы риска 1–4, доменные 👤 ставятся всегда); команда «полный фактчек» → полный. **В промпт включить списком все находки Чуковского `zone: facts` (дословные `quote`) — это его приоритетная очередь проверки** (иначе Факт-флаги молча теряются). Проверяет их реальным поиском (WebSearch/WebFetch). В machine-block для ❌/🟡/⚠️/🕒 — `edit` с верным значением из найденного источника; верного значения нет → `edit: null`. Вердикты → `severity` по таблице. `action`: с верной заменой → `apply`; ❌ без верного значения и 👤 → `flag`; ❓ → `suggest`.
- **Слопотрон**: скил `slopotron`, режим **Detect**, площадка {X}, `previous_skills:[chukovsky]`. Кластер 3+ помечает `blocker, action: redirect` и кладёт в `edit` полный переписанный абзац (без маркеров, без нового смысла). Технические артефакты и прочие точечные правки с дословным `edit` — `action: apply`; одиночные маркеры — `suggest`.

**Шаг 3 — мердж и применение (single-apply) — СКРИПТОМ, не руками.** Собрать `findings[]`
Аграновского и Слопотрона, а также находки Чуковского с `action: flag`, в единый JSON-список (поля
machine-block как есть), записать его и
`text_v1` во временные файлы (временная папка, например `mktemp -d`) и прогнать:
```
python3 {redkollegiya}/apply.py --text {v1} --findings {findings.json} --out {v3} --report {report.json}
```
Скрипт детерминированно выполняет все правила ниже (дедуп, якорение, перекрытие, бюджет роста) и
раскладывает находки по `applied` / `to_author` / `active_blockers` с причиной — Редколлегия берёт
`text_v3` и разделы отчёта из `report.json`, текст сама не правит. Правила — семантика, которую
реализует скрипт (регрессия — `apply.py --selftest`); при расхождении прав скрипт, правило чинится вместе с ним:
- применяются находки `fix` и `blocker` с дословным `edit`;
- `author_choice` (`action: suggest`) в текст НЕ вносится — копится в сводный раздел;
- `flag` в текст НЕ вносится: blocker зон `facts`/`meaning` становится активным (плашка ⛔), остальное — автору;
- `action` не из пяти допустимых → автору с пометкой «неизвестный action», в текст не вносится;
- кластер `redirect` от Слопотрона применяется **дословно из его `edit`** (полный текст абзаца-замены,
  пригодный к прямой подстановке); `edit` неполный или требует смыслового решения → эскалировать в
  `author_choice`, не дописывать самой и **не делать второй слепой LLM-вызов** для разрешения абзаца
  (Инвариант 5 — Редколлегия абзац не сочиняет);
- **якорение:** `quote` ищется в `text_v1` дословно (допуск — только разница пробелов/NBSP/переносов).
  Не найдена или встречается больше одного раза → находка автору, скрипт вхождение не угадывает;
- **одна `quote`, разные `edit` у двух этапов** → конфликт, обе автору; одна `quote` и одинаковый
  `edit` → одна правка с атрибуцией обоих этапов (blocker побеждает fix);
- **вложенная правка:** точечная находка целиком внутри абзаца-замены (факт Аграновского внутри
  кластера Слопотрона) применяется внутри замены, если её `quote` ровно один раз есть в `edit`
  абзаца. Абзац-замена этот фрагмент переписал или выкинул → это перекрытие (следующее правило);
- **перекрытие span двух правок** — геометрически, по позициям в `text_v1`: пересекающиеся правки
  не применяются, обе отдаются автору, самой не разрешать (Инвариант 5). Blocker зоны `facts`
  остаётся активным (см. «Единая шкала»), остальное уходит в `author_choice`;
- **бюджет роста:** суммарный прирост знаков от применённых правок ≤ 20% длины `text_v1`. Сверх
  бюджета вытесняются правки с наибольшим приростом (в `author_choice` с причиной «бюджет роста»).
  **Исправление факта (blocker зоны `facts`) не вытесняется никогда** — это ошибка, а не стиль.
  Кластер Слопотрона — blocker, но вытесняется наравне с fix: абзац-замена и есть то переписывание,
  против которого заведён бюджет. Смысл: детект-этапы правят точечно, и правка, раздувающая текст, —
  симптом переписывания, а не вычитки (замер в gasyoun/RuWritingStyles: доля прогонов без
  переписывания 0,48 → 0,92 после такого ограничителя);
- **`edit` семантически невозможен** (Аграновский нашёл выдуманный факт ❌, но верного значения нет нигде) → НЕ изобретать замену (Инвариант 5): `edit: null`, держать как blocker в разделе «Блокеры» с пометкой «требует ручной правки / фактуры автора».
- **находка `fix` без дословного применимого `edit`** (этап не смог дать верифицированную замену — напр. 🕒 «Устарел» без нового значения) → НЕ чинить самой: понизить в `author_choice` с пометкой «этап не дал замены». Инвариант 5 распространяется на `fix` так же, как на blocker.
- **В режиме Разбор single-apply НЕ выполняется:** `findings[]` копятся в отчёт, текст не меняется (в Разборе `text_v1` := входной текст — Чуковский не переписывает; `text_v3 := text_v1`). Это касается и Шагов 1/4 — в Разборе Чуковский и Розенталь возвращают только `findings[]`, текст не переписывают.

Здесь Редколлегия ближе всего к роли редактора — поэтому правки вносит скрипт, дословно по `edit`,
а своих формулировок Редколлегия не придумывает (см. «Инварианты»). Временные файлы удалить
после Шага 5.

**Коридор объёма этапов-переписчиков (после Шага 1 и Шага 4, режим Правка):**
`python3 {redkollegiya}/apply.py --length-check {до} {после}` — дёшево, прогоняется всегда. Рост > 20% → флаг
`fix`-уровня в «Ключевые флаги»: «{этап} раздул текст на N%» (вычитка не должна дописывать —
сигнал калибровать этап). Потеря > 10%: на лонгриде (>8000 знаков) — аварийный стоп (см. «Контроль
стоимости»), на тексте короче — строка в отчёте (сокращение может быть законной работой Чуковского).

**Шаг 4 — Розенталь (субагент; не отдавать самой слабой модели — гиперкоррекция дороже пропуска).**
Скил `rozental` над `text_v3`, режим {Правка|Разбор}, + `redkollegiya_context`,
`previous_skills:[chukovsky, slopotron, agranovsky]`. Норму ставит по уже очищенному тексту.
Типографику не трогает. → `text_v4`.

**Шаг 5 — Мильчин (Редколлегия сама, без субагента).** Детерминированная типографика **последней** — после всех LLM-проходов (иначе NBSP/ёлочки терялись бы при перепечатке моделью). Какой файл отдавать в `--file`:
- **Полный цикл:** записать `text_v4` в файл черновика Бахтина (это финал, не промежуточная версия) и прогнать `python3 {milchin}/milchin.py --fix --in-place --file {черновик}`.
- **Вычитка без файла-источника** (текст пришёл из чата): записать `text_v4` во временный файл, прогнать с `--fix --in-place`, результат забрать в отчёт, файл удалить.
- **Вычитка файла-источника** (готовый текст лежит в файле автора): файл автора молча НЕ перезаписывать — работать по временной копии (`--fix --in-place` по копии), результат в отчёт; запись в исходный файл — только по «ок» автора (Калибровка).
- **Разбор:** `--check` (только счёт, текст не меняется).

`--fix --in-place` пишет файл на месте атомарно (tmp + os.replace). Собрать единый отчёт.

> **Короткий путь (< 1500 знаков):** относится ТОЛЬКО к этапам ВЫЧИТКИ — их можно выполнить
> инлайн самой, строго по SKILL-файлам соседей, сохраняя порядок и параллельность шага 2 (логически).
> Single-apply Шага 3 и на коротком пути — скриптом `apply.py` (он дешевле ручного прохода).
> Генерации это НЕ касается: в Полном цикле Бахтин всегда запускается субагентом (Редколлегия не
> пишет сама, Инвариант 5). Мильчин — ВСЕГДА финальным запуском скрипта после Розенталя (Инвариант 1).

## Контроль стоимости и латентности

- **Параллель Аграновский ∥ Слопотрон** — главный выигрыш латентности: дорогой фактчек уходит с критического пути.
- **Single-apply вместо 4 переписей** — детект-этапы не переписывают весь текст (экономия выходных токенов), дельты вносит скрипт.
- **Аграновский по умолчанию — быстрый объём** (типы риска 1–4: ссылки/цитаты/числа/сущности — самое опасное у LLM). Полный фактчек — по явной команде «полный фактчек». Доменные 👤 (медицина/право/финансы/налоги) ставятся ВСЕГДА независимо от объёма и эскалируются в blocker — экономим на низкорисковом, не на опасном.
- **Короткий пост (< 1500 знаков)** → этапы вычитки инлайн без субагентов; single-apply и Мильчин всё равно скриптами. Генерация (Бахтин) — всегда субагентом, см. Ф-gen.
- **Аграновский на тексте без фактуры — дёшев, но не пропускается.** Этап всегда запускается; нет объектов риска 1–4 (ссылки/цитаты/числа/сущности) и доменных 👤 → возвращает `findings:[]` без веб-запросов. «Нет фактуры» решает Аграновский внутри этапа, НЕ Редколлегия снаружи (иначе тихий пропуск обязательного этапа).
- **Большой вход (>8000 знаков)** → предупредить автора о стоимости/латентности. Этапы-переписчики (Чуковский/Розенталь) не должны терять абзацы при переписи лонгрида — сверить объём `text_vN` с предыдущей версией (`apply.py --length-check`, см. Шаг 3); заметная потеря (>~10% знаков/абзацев) → остановиться и сообщить (в режиме Правка; в Разборе переписи нет — сверка не нужна). Плотная фактура лонгрида (много объектов риска 1–4) → предложить «полный фактчек».
- В шапку отчёта выводить объём фактчека (быстрый/полный), чтобы стоимость была видна.

## Инварианты — НЕ нарушать

1. **Мильчин — всегда последним и всегда скриптом.** Любая перепись LLM после него вернёт потерю NBSP/ёлочек. Single-apply его не касается — он строго финал. Идемпотентность не трогать.
2. **Дедуп-зоны закреплены.** `previous_skills` их формализует, не переразмечает.
3. **`author_choice` в текст НЕ вносится** — проверить перед выдачей.
4. **Сохраняем только итоговый текст вычитки.** Промежуточные `text_v1/v3/v4` на диск как результат не пишутся. Исключения — носители, а не версии: черновик Бахтина в Полном цикле (вход вычитки, он же файл финала для Мильчина); временный файл для Мильчина при Вычитке из чата; входы и выходы `apply.py` (Шаг 3 и `--length-check` после Шагов 1 и 4). Все временные файлы удаляются после Шага 5.
5. **Редколлегия — тонкий дирижёр, не редактор и не автор** (самый хрупкий инвариант): не пишет текст сама — генерацию делегирует Бахтину; не придумывает правок — дословные `edit` из находок пятёрки применяет скрипт `apply.py`, не рука Редколлегии; перекрытие span, неоднозначная цитата, превышение бюджета роста → эскалация автору, не разрешение Редколлегией.
6. **Аграновский — обязательный, без исключений** («без фактчека» → быстрый объём; «быстрый объём» ≠ пропуск; доменные 👤 — всегда).
7. **Полный цикл не глотает гейты Бахтина.** Гейт понимания задачи Бахтина сохраняется при вызове из Редколлегии — генерим не вслепую. Понимание задачи и анти-слой — зона Бахтина, Редколлегия их не дублирует.
8. **Ф-voice не блокирует.** Нет профиля голоса при нужном голосе → предложить `/vinogradov`, при отказе — нейтральный профиль + предупреждение в отчёт. Отсутствие голоса не останавливает генерацию.
9. **Режим Вычитка не затронут.** Авто-детекция не меняет поведение вычитки готового текста: класс «готовый текст» (без смены голоса) → конвейер пятёрки, блок генерации в отчёте отсутствует. (Класс «текст + смена голоса» → Рерайт, см. Ядро, Шаг A — это осознанное исключение, не вычитка.)

## Калибровка

- **Гейты вычитки:** не спрашивать одобрения МЕЖДУ ЭТАПАМИ ВЫЧИТКИ — прогнать конвейер целиком и показать ОДИН сводный результат. Применять правки к файлу автора — по его «ок».
- **Разрешённые паузы-вопросы (вне этапов вычитки):** (1) гейт понимания задачи Бахтина перед генерацией; (2) гейт неоднозначного режима (Ядро, Шаг B — срабатывает ещё до выбора ветки); (3) вопрос про `/vinogradov` при отсутствующем голосе (Ф-voice); (4) гейт качества черновика (условия и оси — см. Ф-gen; при Факт < 6/10 вариант «продолжить» недоступен). **Внутри самой пятёрки вычитки пауз с вопросом автору нет.** Сверх них — гейт языка RU-first (Ядро, Шаг C), вопрос «жанр без голоса — применить голос {slug}?» (Ф-voice) и аварийный стоп при потере >10% текста на лонгриде (Контроль стоимости).
- Откат правок автором по одному из этапов — сигнал калибровать тот скил, не Редколлегию.
- **После правок Шага 3 или `apply.py`** — `python3 {redkollegiya}/apply.py --selftest` (полный набор PASS).

## Смежное

- Этапы вычитки по отдельности: `/chukovsky`, `/agranovsky` (фактчек), `/slopotron`, `/rozental`, `/milchin`.
- Генерация (этаж выше) → `/bakhtin`; вызывается из Редколлегии в Полном цикле.
- Голос автора → `/vinogradov` собирает профиль голоса из корпуса; Редколлегия проверяет его наличие в Ф-voice.
- Только чистка от AI-маркеров, без остальной вычитки → `/slopotron`.
